原则是**一帧的工作量跟随变化的东西**，空闲窗口不花代价。背后的测量都在进程外进行（每线程周期、上下文切换、DWM 负载、呈现次数），环境是 Windows 11、NVIDIA 显卡、240 Hz 显示器，以 NovaPlayer 为负载。

## 起作用的是什么

- **代价按呈现计。** 驱动在用户态的开销每次呈现都差不多，不论画了什么；少呈现是主要手段。没有损坏的帧不呈现，也没有空闲重复帧。
- **驱动在 UI 线程上提交。** D3D11 设备用 `PREVENT_INTERNAL_THREADING_OPTIMIZATIONS` 创建，驱动不必每次呈现都唤醒自己的工作线程：240 fps 下进程 CPU −22%，上下文切换少四分之一。
- **不空转。** 什么都没画的轮次等到下一次刷新。“每帧都要”用 ticker 表达，而不是零延迟定时器。
- **移动容器只花一个偏移。** 被平移或滚动的元素是一个*偏移组*：后代保留相对于它的位置，移动它只重新定位一个元素，只损坏它的新旧边界。
- **只改裁剪时复用录制**，文字测量不放置字形。
- **按预算交付。** 任务结果每轮最多交付半个刷新周期的量，所以一批结果（两万行标签填充）不会造成一个很长的轮次。

## 数字

测量结果（Mcyc/s：整个进程每秒百万 CPU 周期）：

| 场景 | 之前 | 之后 |
|---|---|---|
| 暂停、歌词页打开 | 18–31 Mcyc/s，每秒 10 次空闲呈现 | 2.7 Mcyc/s，0 次呈现 |
| 240 fps 逐字歌词扫光 | 356 Mcyc/s，DWM 16–25% | 242 Mcyc/s，DWM 9% |
| 两万行标签填充 | 99 Mcyc/s，每秒 1 340 轮，最慢一轮 88 ms | 27 Mcyc/s |

## 测量你的应用

`NOVAUI_TRACE=<file>` 每秒写一行：轮次及其原因（输入、waker、定时器、树的工作、空闲）、帧和呈现、每阶段微秒数（布局、`after_layout`、帧、呈现）、定位/移动/绘制的元素数、命中测试，以及每次唤醒的调用位置。超过 4 ms 的轮次单独占一行。目标：空闲时每秒 0 轮，0 个空损坏帧，每轮最多 2 次布局。

`NOVAUI_AUDIT=1` 在 release 构建里打开 debug 构建的检查：阶段规则和损坏审计——后者把一帧没有绘制的每个元素重新录制一遍，并与它显示的内容比对。
